# 根源追溯（dsh-reason-tree）

把一件事拆成「结论 ← 理由 ← 理由的理由」，画成一棵从下往上长的树。

每一支可以标 **成立** / **不成立** / **待拆**，标完写回文件。想不起来某个结论当时是怎么想的，点「定位至海马体」直接跳过去看原文。

## 安装

```bash
dsh plugin --profile desktop add dsh-reason-tree
```

装完重启 DSH，左侧栏会出现「根源追溯」图标。

## 文件长什么样

一个 `.md` 文件就是一棵树。第一行写结论，下面是缩进列表，2 个空格一层：

```markdown
# 结论：这台机器能用本地模型跑 7B

  [+] 显存够
      显卡 12GB，7B 的 q4 量化大约占 5GB
  [+] 有现成的推理框架
      llama.cpp 和 ollama 都试过，能跑
  [-] 速度能接受
      实测首字延迟 3.2 秒，对话体验太慢
  [?] 能不能用更小的模型
```

- `[+]` 这一支成立
- `[-]` 这一支不成立
- `[?]` 还没拆开

解析时会剥掉这些标记，正文只留结论本身。行尾写 `→ 记忆:主题名` 或 `→ 文件:路径`，节点上会多出一个「关联记忆」区块。

## 目录放哪

默认是 `<工作区>/trace`，也可以在 `~/.dsh/dsh-trace.json` 里指定：

```json
{
  "dir": "D:/notes/追溯",
  "readRoots": ["D:/notes"]
}
```

- `dir`：追溯文件所在目录。
- `readRoots`：面板允许读取的根目录。默认只有工作区和 `~/.dsh`，要读别的地方必须显式加进来——这道闸门是为了让面板不会变成任意文件读取器。

## 和「海马体」联动

装 [海马体](https://github.com/Snerou/dsh-hippo) 之后：

- 点节点详情里的「定位至海马体」→ 海马体飞到对应的文件或那一条结论
- 海马体还没打开也没关系，请求会存 10 分钟，等你点侧栏图标时自动执行

联动走 `localStorage` + `window` 自定义事件，两个插件不需要互相依赖。

## 数据不出本机

只读写你指定的目录，不上传任何东西。
